# True AI Detective — Plan & Board

Single source of truth for the current plan and state. Edited in place to match the latest decisions; history lives in git.

## How we work

- **One story per session.** Claude implements one story, stops, and walks you through the code at a high level.
- **Vertical slices.** Every story is visible end to end (browser or API) and ships with at least one e2e check (Shift Zero gate, see `.shift-zero/PORT.md`).
- **Use libraries directly, as documented.** No custom wrappers or facades over LangChain, LangGraph, OpenAI, CopilotKit, MCP, etc. Tests use the libraries' own fakes (e.g. `GenericFakeChatModel`) or recorded HTTP.
- **Isolation is tested in the story that adds the data.**
- **Deploy early, deploy often.** Railway from S2 onward; no GitHub Actions (D14).
- **New tools are a feature.** Each story lists what you'll learn.

| D17 | Observability | **LangSmith** (EU region), switched on by its own env vars (`LANGSMITH_TRACING`, `LANGSMITH_API_KEY`, `LANGSMITH_ENDPOINT`, `LANGSMITH_PROJECT`); LangChain/LangGraph trace themselves, no code. Set on the api in Railway only; tests never trace. Free tier (5k traces/month, 14-day retention) is for debugging; our own audit log stays the record. Sensitive inputs/outputs redacted before upload (S18) |
| D18 | Evidence analysis | Everything added to the locker is analysed when added, before anything is stored, by one `evidence-analysis` graph routed by kind. **Photos** (jpeg/png/gif/webp, verified by Pillow): the `photo-analysis` graph, EXIF read by code, then one `gpt-5.4-nano` vision call. **Documents** (PDF via pypdf, `text/*`, HTML via trafilatura) and **links** (fetched with httpx, main text via trafilatura): split into LangChain `Document` chunks (4000 chars, overlap 200; PDFs by page), each read in parallel by a `chunk-facts` subgraph (`Send`, max 8 at once, first 100 chunks, the rest noted as a fact). Model answers use Pydantic structured output (OpenAI JSON schema); validator failures and quotes not found in the text go back to the model once with the reason, then only what passed is kept, so every document fact quotes its source verbatim, with its location (page / part). A dead link is kept without facts; a failing model call fails the request. Facts live in `facts` (kind, statement, quote, location, linked to their evidence; RLS by case, a fact's evidence must be in the same case). The api passes the case's facts to the detective as LangGraph runtime context; the system prompt frames them as data, never instructions. **Not done (learning project): SSRF protection for link fetching** (see S22) |
| D19 | Case board | The board (leads, hypotheses, timeline, contradictions) is a key of the detective graph's state, checkpointed per case (RLS like the conversation). An `update_board` node rebuilds it after every reply (nano, Pydantic structured output, not streamed so no board text reaches the chat), citing facts by number; code resolves numbers to the facts and their sources and drops entries citing none. A run with no new client message routes straight to `update_board`: the browser starts one (`copilotkit.runAgent`) after evidence with facts is added. ag-ui-langgraph streams the state as `STATE_SNAPSHOT`; the web reads it with `useAgent({updates: [OnStateChanged]})` (one hook, one chat configuration for the whole case view). The api drops any state the browser sends, so a client can't plant a board. `GET /cases/current/board` serves it on page load |
| D20 | Case memory (RAG) | Facts (statement + quote) and document/page chunks are embedded (`init_embeddings`, `text-embedding-3-small`) into `case_memory` via langchain-postgres `PGVectorStore` (table created by the library in a migration; FKs to case and evidence, RLS like `facts`), after the evidence is committed; if that fails, `detective reindex` rebuilds it (facts + document text from the bucket; links by facts only). The detective graph's `recall` node searches it with the client's message through `as_retriever()`: hybrid vector + Postgres full text (`plainto_tsquery`, every word must match) fused by reciprocal rank fusion, top 8, filtered to the case (+ RLS); the detective sees only what was recalled. A fresh `HybridSearchConfig` per search: langchain-postgres 0.0.19 writes the first query into a shared config and reuses it. No ANN (HNSW) index: per-case filtered search with an ANN index loses the case's own rows; exact search over the case's rows instead. The board still reads all facts. Facts are ordered by an identity `seq` (not `created_at`, which ties within a transaction) |
| D13 | Decision model | JEV (`typesafe-ai/jev`, Vercel AI Gateway) is a candidate for fast typed decisions (next-step routing, relevance scoring). Verified working via AI SDK `experimental_decide` |

## Architecture

```text
Browser ── Next.js + CopilotKit (web service)
              │  AG-UI (SSE) + session cookie
              ▼
          FastAPI (api service) ── LangGraph investigation graph ── OpenAI (chat / vision / image / embeddings)
              │                          │                        └ JEV (typed decisions, TBD S12)
              │                          │ harness tools → (S20) MCP osint server
              ▼                          ▼
          Postgres + pgvector (RLS, checkpoints, audit)     S3 bucket (evidence files, per-case prefix)
```

Current state: Logged-in chat with the detective at https://web-production-7856b.up.railway.app (invite-only; owner page at `/owner`). Each client has one case (Postgres, RLS) whose conversation is stored by LangGraph's Postgres checkpointer (RLS too), shown again on every visit, and can be wiped with **Reset case**. Beside the chat, an **evidence locker** holds the case's photos, files, links and map pins (files in the private Railway Bucket `evidence`); everything added is analysed into facts shown under it, and its facts and text are indexed in the case memory (pgvector, hybrid search) that the detective recalls from on every chat turn: photos (EXIF + nano vision), PDFs, text and linked web pages (chunked, read in parallel, every fact quoting its source with page/part). Above the chat, a **case board** (leads, hypotheses, timeline, contradictions, each citing facts) is rebuilt after every reply and when evidence is added, and streams in live (CopilotKit shared state). `web` (Next.js + CopilotKit) relays auth, cases and chat to `api` (https://api-production-fc37.up.railway.app: `GET /health`, `/auth/*`, `GET /cases/current`, `GET /cases/current/messages`, `GET /cases/current/board`, `DELETE /cases/current`, `/cases/current/evidence` (list, `POST files|links|pins`, `GET {id}/file` → presigned redirect), `POST /agent` = AG-UI stream from a one-node LangGraph detective on `gpt-5.4-nano`) over Railway's private network; every api run is traced to LangSmith (EU, project `true-ai-detective`, grouped by case id as thread); both auto-deploy from `main`, migrations run pre-deploy as the DB owner, the app runs as `detective_app`. Local: `just setup` (once), `just dev` (Postgres + RustFS S3 + api) + `just web`, `just invite <email> <name> [role]`, `just test`, `just check`, `just migration "<msg>"`, `just graphs` (draws each LangGraph graph to `docs/graphs/*.png`), `just reindex` / `just reindex-prod` (rebuild the case memory); deployed: `just smoke <api-url> <web-url>` (smoke client creds in `.env`), `just invite-prod <email> <name> [role]`; infra: `just infra-plan` / `railway config apply`. Config is real env vars only: `just` loads `.env` locally, Railway provides them in prod (secrets `OPENAI_API_KEY`, `APP_DB_PASSWORD` are `preserve()` in IaC); `web/.env` holds committed non-secret web defaults; `Settings` (pydantic-settings) types the api's own config.
